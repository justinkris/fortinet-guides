Chapter Overview

FGCP Clustering Protocol

The FortiGate Clustering Protocol (FGCP) is Fortinet's proprietary HA protocol that groups two to four FortiGate units into a single logical device. All cluster members share the same configuration, firmware, and security policies — the Primary unit handles all management changes and pushes them to Secondary members over dedicated heartbeat interfaces. Heartbeat links carry cluster control traffic, configuration synchronization, and session table replication; they must never carry user data.

FGCP elects a Primary using four criteria checked in order: number of monitored ports up (most wins), HA uptime (longest wins), HA priority (highest wins, configurable 0–255), and serial number (largest wins as tiebreaker). When the Primary fails, the Secondary with the best score immediately takes over, inheriting all virtual MAC addresses and virtual IPs — upstream devices see no change in MAC-to-IP mapping, so ARP caches don't need to flush.

Virtual MACs & Failover

FGCP assigns virtual MAC addresses to all cluster interfaces so upstream switches and routers don't need to relearn ARP entries after a failover. Each interface in the cluster gets a deterministic virtual MAC based on the cluster ID and interface number (format: 00:09:0f:09:<cluster-id>:<interface-id>). When failover occurs, the new Primary assumes these same virtual MACs — from the network's perspective, the MAC-to-IP binding is unchanged.

Session failover ensures that active TCP sessions survive a Primary failure without requiring reconnection. The Primary continuously replicates its session table to the Secondary. The depth of replication is configurable: no session failover (stateless, fastest), main session failover (TCP sessions survive, UDP does not), or full session failover (all sessions including UDP replicated, highest overhead). Virtual clustering extends FGCP to environments with multiple VDOMs — different VDOMs can be Primary on different physical units, spreading load while maintaining full redundancy.

Key distinction: FGCP is a full clustering protocol — all members share a single configuration. FGSP (FortiGate Session Life Support Protocol) is session-only synchronization between independent FortiGate units that each have their own configuration, used in asymmetric routing environments where different paths may handle each direction of a flow.

Active-Active Traffic Flow

In active-active mode, all cluster members actively forward traffic simultaneously. The Primary member acts as a traffic dispatcher, using a load-balancing algorithm (round-robin or based on source IP/port) to distribute new sessions to Secondary members. Secondary members process the traffic and return results — but all forwarded traffic still physically passes through the Primary's interfaces because the virtual MAC is bound there, so asymmetric routing is handled internally.

VRRP (Virtual Router Redundancy Protocol) offers an alternative HA approach that is protocol-standard rather than Fortinet-proprietary. A VRRP group elects a Master router that owns a virtual IP; Backup routers monitor the Master via VRRP advertisements and take over if it stops advertising. Unlike FGCP, VRRP doesn't synchronize session tables or firewall configurations — it only provides gateway redundancy. FortiGate supports VRRP as a supplement to or replacement for FGCP in environments requiring interoperability with third-party devices.
