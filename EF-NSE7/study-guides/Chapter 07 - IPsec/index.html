Chapter Overview

IPsec Topology Design

IPsec VPN topologies on FortiGate fall into three primary patterns. Site-to-site connects two fixed locations with a single bidirectional tunnel — the simplest design, suitable when only two sites need to communicate securely. Hub-and-spoke places a central FortiGate (hub) that all remote sites (spokes) connect to — spokes communicate with each other by routing traffic through the hub, reducing the number of tunnels needed from O(n²) to O(n). Full mesh connects every site to every other site directly — maximum performance and lowest latency between spokes, but tunnel count grows quadratically.

Tunnel aggregation on FortiGate combines multiple parallel tunnels into a single logical interface with load-balancing modes: round-robin (distribute packets), L3/L4 hashing (per-flow), redundant (active/standby), and weighted round-robin (bandwidth-proportional). Route-overlap controls how FortiGate handles multiple tunnels advertising the same destination: use-new (new tunnel wins), use-old (keep existing), or allow (install both and ECMP). SCEP (Simple Certificate Enrollment Protocol) automates certificate lifecycle management for large-scale IPsec deployments.

IKE Phase Configuration

IKE (Internet Key Exchange) negotiates the cryptographic parameters for IPsec tunnels in two phases. Phase 1 (IKE SA) establishes a secure, authenticated channel between peers — both sides agree on encryption algorithm, hash, DH group, and authentication method (pre-shared key or certificate). Phase 2 (Child SA / IPsec SA) negotiates the actual data-protection parameters and derives session keys using the Phase 1 channel.

IKEv2 requires only 4 messages to complete both phases (vs IKEv1's 6–9), supports EAP for flexible user authentication, and uses stronger ciphers by default: AES-GCM, ChaCha20-Poly1305, AES-XCBC. DH groups (Diffie-Hellman) determine key strength: MODP-2048 (Group 14) is minimum recommended; ECP-256 (Group 19) and ECP-384 (Group 20) offer elliptic curve efficiency. PFS (Perfect Forward Secrecy) renegotiates a new DH exchange for every Phase 2 SA — compromising one session key cannot decrypt past or future sessions. DPD (Dead Peer Detection) monitors tunnel liveness: on-demand (check only when traffic fails), on-idle (periodic keepalive), or disable.

IKEv1 vs IKEv2: On FortiGate, IKEv2 is strongly preferred for new deployments. IKEv1 is retained for compatibility with legacy devices. IKEv2's MOBIKE extension also enables tunnel continuity when the client IP changes — critical for mobile users.

Fragmentation & MTU

IPsec encapsulation adds overhead — typically 50–100 bytes per packet for ESP headers, IV, padding, and authentication. This means a standard 1500-byte Ethernet MTU becomes too large for the encapsulated packet to traverse the internet without fragmentation. PMTUD (Path MTU Discovery) is the mechanism by which hosts discover the smallest MTU along a path by sending packets with the DF (Don't Fragment) bit set and waiting for ICMP "fragmentation needed" messages back. TCP MSS clamping on FortiGate adjusts the TCP Maximum Segment Size in SYN packets to prevent oversized TCP segments, solving the problem proactively without relying on ICMP.

When PMTUD is blocked (common on misconfigured networks that drop ICMP), packets silently fail. FortiGate's IP fragmentation settings control whether the FortiGate itself fragments oversized packets before encapsulation. The MF (More Fragments) bit indicates there are more fragments following. FEC (Forward Error Correction) adds redundant data to UDP streams across lossy links, allowing the receiver to reconstruct lost packets without retransmission — useful for ADVPN and SD-WAN overlays across unreliable WAN connections.
