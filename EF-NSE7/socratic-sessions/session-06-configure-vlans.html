Before You Begin · Real-World Scenario

The IoT Camera That Owned the CEO's Email

Varco Manufacturing had expanded aggressively over four years, and their factory floor network had grown by accretion. Original CAT5 runs from the 2009 factory build shared infrastructure with the corporate LAN — both factory floor IoT sensors and the C-suite's laptops resolved DHCP addresses from the same 10.0.0.0/16 pool. When the facilities team added twelve IP surveillance cameras in 2021 to monitor the production line, the installer connected them to the nearest available switch ports and assigned them to the same LAN segment. Nobody noticed. Nobody thought to notice. The cameras ran firmware from 2019 and had default admin credentials — admin/admin — that had never been changed. By 2023, two of the cameras had been compromised by a botnet that exploited an unpatched RTSP vulnerability.

The attacker who found those cameras spent three weeks quietly mapping the network from the camera's vantage point. Because the cameras shared a segment with office workstations, they could see SMB broadcast traffic. Because those workstations had network drives mapped to the corporate file server — also on the same flat LAN — the attacker used pass-the-hash techniques to laterally move from the camera to a workstation to the file server. The CEO's email archive was stored in a shared PST on that file server. By the time the SOC analyst noticed the unusual outbound transfer — 4.2 gigabytes to a residential IP in Eastern Europe — the exfiltration was complete. The breach notification letters cost Varco more than the entire IT infrastructure they had been managing for a decade.

The network audit conducted afterward produced a single-paragraph root cause: no VLANs. The IoT cameras should have been on their own isolated VLAN — VLAN 30, say — with a FortiGate policy allowing only outbound RTSP to the on-premises NVR, and no routing to any other segment. The corporate workstations on VLAN 10, the servers on VLAN 20, and the IoT devices on VLAN 30 would have been logically separate despite sharing physical switch infrastructure. The camera compromise would have been contained to VLAN 30 with zero path to corporate assets. This session is about understanding the 802.1Q tagging model, how FortiGate VLAN subinterfaces work, and how inter-VLAN firewall policies enforce the segmentation that containment requires.

Overview

802.1Q VLANs are the fundamental mechanism for creating multiple logical networks on shared physical infrastructure. The standard works by inserting a 4-byte tag into the Ethernet frame header — the tag contains a 12-bit VLAN ID, allowing up to 4,094 distinct VLANs on the same physical medium. A switch port configured as a trunk carries multiple VLANs simultaneously, tagging outgoing frames and reading tags on incoming frames to direct them to the correct VLAN context. An access port, by contrast, carries only one VLAN and strips the tag before delivery to the connected end device — the device itself is unaware it is on a VLAN.

On FortiGate, VLANs are implemented as subinterfaces of a physical or logical parent interface. A subinterface is a virtual interface bound to a specific VLAN ID — it has its own IP address, security zone assignment, and DHCP server configuration. When a tagged frame arrives on a trunk link connected to the FortiGate's physical interface, FortiGate reads the VLAN tag and delivers the frame to the matching subinterface. Firewall policies then apply between subinterfaces exactly as they apply between physical interfaces — meaning inter-VLAN routing is controlled and inspected by FortiGate security policies. This is the architectural basis for software-defined segmentation on a single physical appliance.

FortiGate also supports hardware switch interfaces and software switch interfaces — both of which create a switching fabric between multiple physical ports. Understanding when to use a switch interface versus a routed interface with VLAN subinterfaces is an important design distinction that the NSE7 exam tests. Additionally, link aggregation (802.3ad LACP) allows multiple physical ports to be bonded into a single logical interface for redundancy and bandwidth, and VLANs can be configured on top of an aggregate interface just as on a single physical port.
